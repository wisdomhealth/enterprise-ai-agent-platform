# 客服转人工运行手册

## 状态与所有权

会话按 `AI_ACTIVE → HANDOFF_REQUESTED → QUEUED → HUMAN_ACTIVE` 转移。客服认领使用
`QUEUED + version` 的数据库条件更新；冲突响应必须显示当前状态和版本。`HUMAN_ACTIVE`
只能由客服显式执行 **Resume AI** 回到 `AI_ACTIVE`，绝不会因超时、离线、刷新或重启自动恢复。

## 触发与快照

客户主动请求、低置信/拒答、连续两次失败、敏感主题以及已安全持久化的系统错误都会建立持久化
handoff。快照保存消息引用、会话摘要位置、客户可选联系信息、客户安全引用、工具结果和最后一条
客户消息序号；不保存令牌、提供商密钥或未处理的模型错误。

## 恢复与安全

Resume AI 会将接管边界及之前的所有待处理或运行中 `chat.answer` 任务置为终止状态。它不会补发
人工接管期间遗留的 AI 输出，系统等待下一条客户消息或新的显式触发。客服回复、解决和恢复 AI
均受组织边界、角色、认领人和乐观版本控制约束，并会生成审计与 Outbox 事件。

离线客户的可选姓名和邮箱仅随 handoff 快照持久化；队列和交接快照均以 PostgreSQL 为权威来源。
